## 리액트 - 업무 관리 프로젝트

## EditModal과 LoggerModal 구현

이번에는 `EditModal` 과 `LoggerModal` 을 구현했어요.  
기존에 만들었던 흐름과 크게 다르지 않아서 새로운 개념보다는 구현을 이어가는 느낌이었어요.

## 스타일 수정

구현을 진행하면서 강의 화면과 결과가 조금 다르게 보인 부분이 있어서 몇 가지 스타일을 수정했어요.

## DropDownForm

`DropDownForm` 에서는 버튼 너비에 비해 글자 크기가 커서 텍스트가 아래로 내려가는 문제가 있었어요.  
그래서 `fontSize` 를 한 단계 줄여서 맞췄어요.

```ts
export const button = style({
  width: 150,
  color: vars.color.brightText,
  padding: vars.spacing.medium,
  fontSize: vars.fontSizing.T4,
  backgroundColor: vars.color.mainDarker,
  border: "none",
  cursor: "pointer",
  ":hover": {
    backgroundColor: vars.color.mainFaded,
  },
});
```

## EditModal

`EditModal` 에서는 `input` 의 크기가 예상보다 커지면서 스크롤이 생기는 문제가 있었어요.  
이 부분은 `boxSizing` 속성을 추가해 크기 계산 기준을 맞춰 해결했어요.

```ts
export const input = style({
  width: "100%",
  minHeight: "30px",
  border: "none",
  borderRadius: 5,
  marginBottom: vars.spacing.big2,
  padding: vars.spacing.medium,
  fontSize: vars.fontSizing.T4,
  boxShadow: vars.shadow.basic,
  boxSizing: "border-box",
});
```

또 아래쪽 여백이 조금 과하게 느껴져서 버튼 영역의 여백도 함께 정리했어요.

```ts
export const buttons = style({
  display: "flex",
  justifyContent: "space-around",
});
```

## BoardList

`BoardList` 에서는 선택된 게시판과 선택되지 않은 게시판의 색상을 서로 바꿨어요.  
기존에는 선택된 게시판이 회색이었는데, 개인적으로는 회색이 비활성 상태처럼 보여서 더 자연스럽게 보이도록 수정했어요.

```ts
export const boardItem = style({
  color: vars.color.brightText,
  fontSize: vars.fontSizing.T3,
  backgroundColor: vars.color.selectedTab,
  padding: vars.spacing.medium,
  borderRadius: 10,
  cursor: "pointer",
  marginRight: vars.spacing.big1,
  ":hover": {
    opacity: 0.8,
    transform: "scale(1.03)",
  },
});

export const boardItemActive = style({
  color: vars.color.brightText,
  fontSize: vars.fontSizing.T3,
  backgroundColor: vars.color.mainFaded,
  padding: vars.spacing.medium,
  borderRadius: 10,
  cursor: "pointer",
  marginRight: vars.spacing.big1,
});
```

## 의문이 들었던 부분

구현을 따라가다 보면 코드가 동작하는 건 이해되는데, 왜 이런 방식으로 작성했는지가 궁금할 때가 있어요.  
이번에도 그런 부분을 몇 가지 정리해 봤어요.

## selector로 가져온 값을 다시 state에 저장하는 이유

`EditModal` 에서는 `selector` 로 가져온 값을 바로 수정하지 않고, 다시 `state` 에 담아서 사용하고 있었어요.

```tsx
const editingState = useTypedSelector((state) => state.modal);
const [data, setData] = useState(editingState);
```

이렇게 하는 이유는 `store` 에 들어 있는 값을 직접 수정할 수 없기 때문이에요.  
`store` 의 값은 `dispatch` 를 통해 바꿔야 하고, 입력창에서 사용자가 타이핑하는 중간 과정처럼 즉시 변하는 값은 지역 `state` 로 다루는 편이 자연스러워요.  
즉, 화면에서 먼저 `state` 로 값을 바꾸면서 보여 주고, 수정이 끝났을 때 최종적으로 `dispatch` 를 통해 `store` 를 갱신하는 구조예요.

## EditModal의 onChange 함수를 나눠서 작성한 이유

입력값을 바꾸는 함수는 하나로 합칠 수도 있어요.  
예를 들어 `name` 속성을 활용하면 하나의 함수로 여러 입력을 처리할 수 있어요.

```tsx
const handleEditInput = (e: ChangeEvent<HTMLInputElement>) => {
  const taskName = e.target.name === "title" ? e.target.value : data.task.taskName;
  const taskDescription =
    e.target.name === "description" ? e.target.value : data.task.taskDescription;
  const taskOwner = e.target.name === "author" ? e.target.value : data.task.taskOwner;

  setData({
    ...data,
    task: {
      ...data.task,
      taskName,
      taskDescription,
      taskOwner,
    },
  });
};
```

그런데 강의에서는 각 입력마다 함수를 따로 두는 방식으로 작성했어요.

```tsx
const handleNameChange = (e: ChangeEvent<HTMLInputElement>) => {
  setData({
    ...data,
    task: {
      ...data.task,
      taskName: e.target.value,
    },
  });
};

const handleDescriptionChange = (e: ChangeEvent<HTMLInputElement>) => {
  setData({
    ...data,
    task: {
      ...data.task,
      taskDescription: e.target.value,
    },
  });
};

const handleAuthorChange = (e: ChangeEvent<HTMLInputElement>) => {
  setData({
    ...data,
    task: {
      ...data.task,
      taskOwner: e.target.value,
    },
  });
};
```

이 방식은 함수 수는 늘어나지만, 각각 어떤 입력을 처리하는지 바로 드러난다는 장점이 있어요.  
그래서 재사용성보다는 가독성과 명확함을 더 우선한 방식으로 볼 수 있어요.

## Redux Toolkit에서 push를 써도 되는 이유

`boardsSlice` 에서 `addBoard` 를 만들 때 배열에 `push` 를 사용하는 부분도 눈에 들어왔어요.  
일반적으로는 배열에 직접 `push` 하면 원본이 바뀌기 때문에 불변성을 해친다고 배우는데, 여기서는 Redux Toolkit 이 내부적으로 `immer` 를 사용하고 있어서 이런 코드도 안전하게 처리돼요.

즉, 겉으로 보기에는 직접 수정하는 것처럼 보여도 내부에서는 불변성을 유지하는 새로운 상태가 만들어져요.  
다만 이건 `push` 만 특별히 허용되는 것이 아니라, `immer` 가 감지할 수 있는 변경 방식 전반에 적용된다고 이해하면 돼요.
