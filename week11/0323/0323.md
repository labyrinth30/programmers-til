지난 시간까지 타입스크립트와 리액트의 기초를 다루었어요. 이번 시간부터는 리액트를 활용해 본격적인 업무 관리 프로젝트를 진행해 볼게요.

## 프로젝트 구조 및 패키지

프로젝트의 기본적인 폴더 구조와 사용된 주요 패키지들을 정리했어요.

**폴더 구조**
- `components` : 컴포넌트들을 모아두는 폴더예요.
- `hooks` : 커스텀 훅 코드를 작성해요.
- `store` : 상태 관리 라이브러리(Redux 등) 관련 코드를 작성해요.
- `reducer` : 슬라이스(Slice)에 있는 리듀서들의 집합이에요.
- `slices` : Redux Toolkit의 슬라이스 집합이에요.
- `types` : 사용자 정의 타입들을 모아두는 폴더예요.

**주요 패키지**
- `@reduxjs/toolkit` , `react-redux` , `redux` : 전역 상태 관리를 위해 사용해요.
- `clsx` : 조건부로 클래스명을 결합할 때 유용해요.
- `@vanilla-extract/css` , `@vanilla-extract/css-utils` , `@vanilla-extract/vite-plugin` : CSS-in-JS 방식으로 스타일을 변수처럼 다루고 Vite와 연동하기 위해 사용해요.
- `react-icons` : 다양한 아이콘을 쉽게 불러와 사용할 수 있어요.
- `uuid` : 고유한 ID 값을 생성할 때 사용해요.
- `react-beautiful-dnd` : 드래그 앤 드롭 기능을 구현할 때 사용해요.

(VSCode 확장 프로그램 중 'ES7+ React/Redux/React-Native snippets'를 설치하면 `rafce` 같은 단축어로 함수형 컴포넌트를 빠르게 생성할 수 있어 편리해요.)

## Redux를 활용한 상태 관리

Redux는 전역 상태 관리 라이브러리예요. 프로젝트 규모가 커지면 `props` 만으로 상태를 전달하기 어려워지고 코드가 복잡해져요. 이때 Redux를 사용하면 여러 컴포넌트에서 상태를 전역 변수처럼 쉽게 공유할 수 있어요.

**Redux Toolkit 흐름(Flow)**
1. **Slice 생성 (Sub Reducer 생성)**: `@reduxjs/toolkit` 의 `createSlice()` 를 사용해요.
2. **Reducer 생성**: 생성된 슬라이스들을 모아 하나의 Reducer로 만들어요.
3. **Store 생성**: `configureStore()` 를 사용해 Reducer를 바탕으로 Store를 생성해요.
4. **동작**: Action(객체) 발생 -> Dispatch(함수) 실행 -> Reducer가 타입에 따라 상태 반환 -> Store 상태 업데이트 -> 컴포넌트 리렌더링.

## 커스텀 훅 만들기 (Redux with TS)

타입스크립트를 사용할 때 자동 타입 추론이 되지 않는 경우에는 직접 타입을 지정해 주어야 해요. Redux의 `useSelector` 나 `useDispatch` 를 사용할 때도 매번 RootState나 AppDispatch 타입을 지정해 주는 것은 번거로워요. 이를 해결하기 위해 타입을 미리 지정해 둔 커스텀 훅을 만들어 사용하면 편리해요.

```typescript
// store/index.ts
import { configureStore } from "@reduxjs/toolkit";
import reducer from "./reducer/reducer";

const store = configureStore({
  reducer,
});

export type RootState = ReturnType<typeof store.getState>;
export type AppDispatch = typeof store.dispatch;
export default store;
```

```typescript
// hooks/redux.ts
import { TypedUseSelectorHook, useDispatch, useSelector } from "react-redux";
import { AppDispatch, RootState } from "../store";

// 제네릭(Generic)을 활용해 타입을 미리 지정한 커스텀 훅이에요.
export const useTypedSelector: TypedUseSelectorHook<RootState> = useSelector;
export const useTypedDispatch = () => useDispatch<AppDispatch>();
```

## 전역 스타일 생성 (Vanilla Extract)

이번 프로젝트에서는 일반적인 `.css` 파일 대신 `@vanilla-extract/css` 라이브러리를 활용해 `.css.ts` 파일로 스타일을 관리해요. 이 방식을 사용하면 스타일을 변수처럼 다룰 수 있어 유용해요.

Vite 환경에서 사용하려면 먼저 `vite.config.ts` 에 플러그인 설정을 추가해야 해요.

```typescript
// vite.config.ts
import { defineConfig } from "vite";
import react from "@vitejs/plugin-react";
import { vanillaExtractPlugin } from "@vanilla-extract/vite-plugin";

export default defineConfig({
  plugins: [react(), vanillaExtractPlugin()],
});
```

이후 `createGlobalTheme` 과 `style` 함수를 사용해 전역 테마와 스타일을 정의하고 컴포넌트에서 불러와 사용해요. (`:root` 의사 클래스를 기준으로 전역 변수를 생성해요.)

```typescript
// App.css.ts
import { createGlobalTheme, style } from "@vanilla-extract/css";

export const vars = createGlobalTheme(":root", {
  color: {},
  fontSizing: {}
});

export const appContainer = style({
  // 스타일 작성
});

export const buttons = style({
  marginTop: "auto",
  paddingLeft: vars.spacing.big2,
});
```

```tsx
// App.tsx
import { appContainer, board, buttons } from "./App.css";

function App() {
  return (
    <div className={appContainer}>
      <div className={board}></div>
      <div className={buttons}>
        <button></button>
      </div>
    </div>
  );
}

export default App;
```

## 타입스크립트 유틸리티 타입과 제네릭

**ReturnType 유틸리티 타입**
타입스크립트에는 여러 유틸리티 타입이 존재해요. 그중 `ReturnType<T>` 는 특정 함수 타입이 반환하는 타입을 추출하여 새로운 타입으로 만들어주는 역할을 해요.

```typescript
function func(v: string): number {
  return +v;
}

// func 함수의 반환 타입인 number를 추출해 Type으로 지정해요.
type Type = ReturnType<typeof func>; 

const a: Type = 1234; // 정상 동작
// const b: Type = 'text'; // 에러: string 타입은 number 타입에 할당할 수 없어요.
```

**제네릭 (Generic)**
제네릭은 타입을 변수처럼 다루어, 함수나 클래스를 정의할 때가 아닌 실제 사용할 때 타입을 지정할 수 있게 해주는 문법이에요. 제네릭을 활용하면 타입 안전성을 유지하면서 코드의 재사용성을 크게 높일 수 있어요.

```typescript
function generic<T>(x: T): T {
  return x;
}

generic<number>(1); 
// 내부적으로 아래와 같이 동작해요.
// function generic(x: number): number { return x; }

generic<string>('hi'); 
// 내부적으로 아래와 같이 동작해요.
// function generic(x: string): string { return x; }
```
